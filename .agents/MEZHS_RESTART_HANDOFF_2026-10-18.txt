LESSONS LEARNED
---------------
1. Verify the EXISTING runtime before adding features. Start with
   Agent/policy lists, model discovery/selection, chat history, normal
   text-only Chat, text-only Agent execution, and expected UI controls.
2. Keep each task narrow, auditable, reversible and separately tested.
   Do not simultaneously change provider code, Agent persistence,
   normal Chat, Agent Web and the shared API.
3. The upload primitive is exactly ONE host-local file path per call,
   handled by the selected provider integration. To upload ten files,
   call it ten times. Let the provider reject the eleventh if needed;
   MEŽS does not impose or anticipate provider file quotas.
4. Do not copy input bytes to MEŽS storage, use browser multipart/file
   bytes, batch file-path arrays, generic extension/MIME whitelists,
   content validators, arbitrary maximum image dimensions, or other
   speculative acceptance rules. Keep only metadata necessary for the
   actually observed provider protocol.
5. A provider may require image width/height when ATTACHING the file
   to a message; that is protocol metadata, not permission for MEŽS to
   implement a homegrown image validation framework.
6. Uploading and sending a conversation turn are distinct operations.
   Keep only minimal provider file references for later attachment.
   Do not automatically retry a semantic turn if provider acceptance
   is uncertain. Avoid duplicate commands/responses.
7. Browser JavaScript cannot obtain arbitrary full local host paths
   from a normal HTML file picker. For host-local uploads, use a typed
   path if and when a frontend is added; do not pretend the browser
   can provide unrestricted filesystem paths.
8. Because this API opens local files on the host, it must remain
   restricted to trusted local clients; never expose it as a remotely
   callable arbitrary filesystem-read API.
9. Each Git worktree has separate ignored npm/node_modules state.
   The Visual Studio task worktree previously lacked:
     <worktree>\electron\node_modules\electron\path.txt
   while isolated tests used Electron from a DIFFERENT worktree.
   Check transport.electronDirectory, module paths, working directory
   and runtime dependencies before blaming code or a branch switch.
10. CI, mock provider tests and an isolated browser are not substitutes
    for a live real-account upload and a real user-facing UI smoke test.
11. Avoid unrelated changes to Agent/policy/model UI and unrelated
    refactors while solving an attachment requirement. Regressions
    in these paths are blocking.
12. Do not add defensive retry systems, compatibility fallbacks,
    validators or generic frameworks without a demonstrated need.
13. Leave browser profiles, untracked ignored builds, active sessions
    and running Agent executions alone unless explicitly authorized.
14. Reports sent through MEŽS must be PLAIN MARKDOWN without custom
    HTML/XML/UI tags such as <badge>, <box> or <text>; its command
    parser has rejected those tags.
15. Keep PR #30 independent. Its Electron diagnostics refactor was
    tested, but its original base is now stale after the rollback.
16. Never treat green automation as proof of root cause or of working
    runtime UI. Distinguish observed facts from hypotheses.
